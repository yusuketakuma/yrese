# 16 — 主操作者調査: 誰が調剤レセコンを操作するか(2026-07-31)

> **RESEARCH RECORD(non-SSOT 作業領域)** — 情報源は repository SSOT(Priority 準拠)と
> **Priority C(公開 Web 記事)**の混在である。Priority C 部分は傾向把握の参照のみに使い、
> 実装根拠(evidence_id の源泉)には使用しない(PRD-004 冒頭宣言と同じ規律)。

## 1. 調査の問い

yrese は事務員がメインで使うことを想定しているか。業界の調剤レセコン運用実態はどうか。
丁「一枚盤面」(14号)の設計へ何を反映すべきか。

## 2. リポジトリ SSOT 上の事実(evidence 付き)

| 事実 | Evidence |
|---|---|
| ロールは pharmacist / clerk / admin / support の4種 | shared-kernel `ROLE_NAMES` / 01号 §1 |
| 事務(clerk)ホーム最優先 = 受付キュー・入力中下書き・帳票失敗・未収 | UIX-006 §4(APPROVED) |
| 薬剤師ホーム最優先 = 確認待ち・疑義照会中・CRITICAL警告・要再検証 | UIX-006 §4(APPROVED) |
| 薬剤師確認は scope で専権化(`prescription:confirm` / `dispensing:confirm`)し、スキップ一括確定は禁止遷移 | DOM-004 §1 遷移ガード・禁止遷移 |
| 処方入力の受入基準に「キーボード完結・薬剤師確認前後の状態分離」 | PRD 系 mvp_scope M4(**status: PROPOSED — 未承認**。2026-07-31 checker L-2 訂正) |
| 体験品質の競争線に「熟練者=ショートカット高速入力/初心者=ガイドで迷わない」の二重UX | PRD-004 §2(調剤くんV8 反映点。**status: PROPOSED — 未承認**。同上) |

**結論(repo)**: 「事務員がメイン」とは定義されていない。**操作回数の主ユーザーは事務、
安全確定の主役は薬剤師**という二層モデルが SSOT 全体(UIX-006/DOM-004/UIX-001 P-07)で一貫している。

## 3. 業界実態(Priority C — 参照のみ)

1. **レセコン入力は基本的に調剤薬局事務が担当**(受付・入力・請求・会計が事務の中核業務)。
   ただし**一人薬剤師の薬局では薬剤師自身が入力**し、報酬点数算定の判断は薬剤師と事務が
   連携して行う。
2. **0402通知(2019-04-02 厚労省「調剤業務のあり方について」)**により、非薬剤師の対物業務
   (ピッキング・一包化の補助・在庫管理等)が要件付きで正式に認められ、薬剤師を対人業務へ
   シフトさせる構造変化が進行。レセコン操作の事務比重は増加方向。
3. **市場構造**: EMシステムズ+PHC の上位2社で国内シェア5割超、上位数社で8割近く。
   ベンダー各社の訴求(入力の速さ・1画面表示・請求前チェック)は事務の操作効率と
   薬剤師の監査効率の両輪(PRD-004 §1 と整合)。

**結論(業界)**: yrese の二層モデルは業界標準の分担(事務=主操作者、薬剤師=監査・確認・対人)
と一致する。加えて**一人薬剤師=ロール兼任**という実在の運用形態を UI が想定する必要がある。

## 4. 丁「一枚盤面」への反映事項

| # | 反映 | 行き先 |
|---|---|---|
| F-1 | **ロール別盤面ビュー**: 同じ調剤盤を、事務ビュー(入力工程の展開が既定・受付キュー主役)と薬剤師ビュー(確認待ちキュー主役・CRITICAL/要再検証が前景)で投影を変える。権限は従来どおり API 側 scope が正(P-14) | **14号 §7 として具体化済み(2026-07-31 v0.2.0)** |
| F-2 | **並行作業の実在確認**: 事務が入力中の患者を薬剤師が確認する同時操作は業界標準運用 — R-3(ロック表現)は仮説でなく必須要件 | 14号 R-3(裏付け) |
| F-3 | **一人薬剤師モード**: clerk 不在で pharmacist が全工程を操作する兼任形態。盤面は統合ビューを提供しつつ、確認操作の scope 検証は緩めない(自己入力+自己確認の記録分離) | 15号 §9 へ追記(本日実施) |
| F-4 | **キーボード完結**: 工程行の展開フォームは Tab 移動・ショートカットで完結できること(事務の熟練操作)。二重UX(ガイド/高速)は UIX-002/004 改版事項(PRD-004 既記載) | UIX-008 候補の検証要件(昇格時) |
