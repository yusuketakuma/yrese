1. **遷移の三置換**: 「対象を変える=選択(常設キュー)」「工程を進める=展開(工程行)」
   「根拠を確かめる=ドロワー(その場)」。典型1患者の完了は現行11遷移 → 0遷移。
2. **3盤面への再編**: active 28画面(UIX-007)は廃止せず「調剤盤・請求盤・管理盤」の
   3盤面+常設レール+ドロワーへ写像する。
   **写像表の所在(2026-07-31 checker H-3 訂正)**: 写像表の内容は現在リポジトリ外の
   Artifact(cb24845f プロトタイプ §再編)にのみ存在し、**リポジトリ内文書へ未転記**である。
   fresh-context checker も将来の監査も参照できないため、**転記完了まで UIX-007 改版
   (WP-5105)は起案不能**(PRC-007 の source_refs 検証可能性を満たさない)。
   請求・管理を調剤盤に混ぜないのは不可逆操作の隔離と権限境界のため(P-11/P-14)。
3. **常設レイアウト**: 左=受付キュー(SCR-001/002 吸収)、中央=患者フォーカスフレーム+
   工程アコーディオン、右=警告・状態レール(SCR-013 吸収)。
4. **P-01 整合規律**: 折りたたみ可能なのは入力フォームのみ。状態 chip・工程サマリ・警告は
   畳んでも常時可視。安全情報を展開部に置くことを型・テストで禁止する(要設計 — §5)。
5. **確定の演出(2026-07-31 checker H-2 / D-2 整合訂正)**: 薬剤師確認の記録で紙面が
   仮トーンから確定トーンへ転じる。ただし転換は **D-2 の2段分離(17号 §2)に従い
   段1(ローカル確定)のみを表現**し、外部登録の状態は「確定 ●」chip と別の
   「登録 ↻ / ●」chip の**併置**で示す。外部登録未完了の状態を確定と同一の
   単一成功表現で束ねない(UIX-001 禁止3 / H-03)。
   仮/確定の区別は点線/実線の**形状のみに依存せず**、シート見出しの
   テキストラベル(仮 / 確定)と確認者・確認日時の常時表示を伴う
   (P-05「ラベル+枠」/ P-06「視覚・文言両方」/ P-07。07号 H-04 の緩和策 —
   forced-colors・印刷・圧縮密度で破線が消えても文言で判別可能にする)。
6. **SCR-028(監査ログ閲覧)は RETIRED のまま** — 一枚盤面にも置かない。

## 7. ロール別盤面ビューと並行作業の設計解(2026-07-31 改版 — R-3 / 16号 F-1・F-2)

主操作者調査(16号)を受け、R-3 の設計解を次のとおり定める。実装は §4 の前提条件に従う。

### 7.1 ロール別ビュー = 同一盤面の投影(権限ではない)

調剤盤は単一の正本であり、ロール別ビューは**表示の投影のみ**を変える。
権限の正は従来どおり API 側 scope(deny-by-default)であり、ビュー切替は権限を一切変えない(P-14)。

**投影の安全不変量(2026-07-31 checker M-6 追加)**: BLOCKER / CRITICAL 警告・
患者文脈(P-09)・システムモード(P-03)は**ロール投影の対象外**であり、
どのビューでも前景から降格しない(UIX-001 §5 は CRITICAL に確認操作必須を課しており、
投影で「前景固定」から外れてよい種類の情報ではない)。

**キューの fail-closed(2026-07-31 checker C-2 追加)**: キューの導出元工程が
`UNAVAILABLE`(契約未承認・未接続 — 15号)であるとき、キューを**空表示にしない**。
「空(対象ゼロ)」と「導出不能(未接続)」を必ず区別し、後者は UNAVAILABLE の
理由表示へ倒す。特に薬剤師ビューの確認待ちキューは `PHARMACIST_CONFIRMATION` が
UNAVAILABLE である間、空キュー(=「確認待ちゼロ」と誤読される)ではなく
未接続表示を出す。

**ロールの正本(2026-07-31 checker H-4 訂正)**: ビューの軸は shared-kernel
`ROLE_NAMES`(pharmacist / clerk / admin / support)であり、「兼任」は**独立ロールではなく
pharmacist ロールの表示プリセット**である(MOD-007 / ROLE_NAMES を変更しない)。
また runtime のロール供給源は現行 whoami 契約に存在しない(`{tenantId, pharmacyId,
actorId, scopes}` のみ — checker 実測)。**ビュー既定の決定は scope 集合からの投影として
設計するか、whoami 契約へのロール追加(契約変更 WP)を要する** — どちらかの決定が
WP-5113 着手の前提【要設計】。

| ビュー | 主役 | 工程行の既定 | 前景に固定 |
|---|---|---|---|
| 事務(clerk) | 受付キュー(左レール) | 入力系(保険確認・処方入力・会計・帳票)を展開既定。確認系は読み取りサマリ | 入力中下書き・帳票失敗・未収(UIX-006 §4 準拠)+安全不変量 |
| 薬剤師(pharmacist) | **確認待ちキュー**(薬剤師確認工程に到達した患者。並び順は §7.3 未決 — 薬剤師レビュー) | 確認系(調剤・算定 trace・薬剤師確認)を展開既定。入力系は参照+差し戻し導線 | CRITICAL 警告・疑義照会中・要再検証(UIX-006 §4 準拠) |
| 管理者(admin) | 管理盤がホーム(調剤盤は閲覧投影) | — | モード・同期・マスター・月次締め状況+安全不変量 |
| サポート(support) | 障害状況・診断情報のみ | — | **PHI 非表示投影**(UIX-006 §4 の明示要求。氏名・カナ・生年月日・患者番号を含む全 PHI を表示しない) |
| 兼任(pharmacist の表示プリセット) | 統合ビュー(事務ビュー+確認待ちキュー併置) | **確認操作到達時は確認系(調剤・算定 trace・薬剤師確認)を強制展開**(fail-closed 側の既定 — 2026-07-31 checker H-3 訂正。根拠を開かないまま最終確定に到達する既定導線を作らない。既定の妥当性は薬剤師 human gate【薬剤師レビュー】) | 確認操作時も scope 検証・自己入力+自己確認の記録分離を緩めない(15号 §9) |

### 7.2 並行作業の編集所有とロック表現

1. **閲覧は常時自由・編集は患者×工程で単一所有。** 同一患者の同一工程を編集できる端末は
   同時に1つ。異なる工程(事務が会計準備・薬剤師が調剤確認)は並行編集可。
   ロック粒度は **workflow-stage enum の工程単位**(15号)であり、表示上の統合行
   (会計+帳票の1行表示)とは無関係 — PAYMENT と DOCUMENT_OUTPUT は別ロック(17号 SF-4)。
2. **ロックは隠さず表示する。** 編集中の工程行には状態インクで
   「↻ 入力中 — 事務 田村(端末2)」を常時表示(pending トーン+操作者+端末)。
   無言のグレーアウトを禁止し、「誰が・どこで」を必ず添える(P-19 と同型の理由提示)。
3. **最終防衛は DOM-004 遷移ガード。** UI ロックは表現であって防衛ではない。
   stale 状態からの確認・確定は API 側の遷移ガード/版検証で拒否し(412/conflict)、
   競合は自動補正せず人間へ返す(CONFLICT_REQUIRES_HUMAN_REVIEW 原則の踏襲)。
4. **確認操作は編集ロックと独立。** 薬剤師確認は「その時点の確定対象(版)」への署名であり、
   署名対象の版が変わっていれば必ず失敗する(丁の確定演出は版一致時のみ発火)。

- 「差し戻し」導線の遷移定義(DOM-004 の禁止遷移と矛盾しない範囲の設計)【SSOT 突合】
- 確認待ちキューの並び順(到達順・待ち時間・重症度の優先度設計)【薬剤師レビュー】
- **入力中フォームを保持したままの患者切替の扱い**(2026-07-31 checker C-3 追加)—
  一枚盤面ではキュー選択1クリックで中央の患者文脈が遷移なしに入れ替わる。
  展開中フォームの入力値の破棄/保持/警告、および 07号 H-01 の緩和策
  「選択時に生年月日再確認」が常設キューからの即時選択で成立する導線
  【medical_safety + 薬剤師レビュー】
- **07号 use-error hazard register の丁構造での再導出**(2026-07-31 checker C-3 追加)—
  H-01(患者取り違え)/ H-02(患者文脈喪失・残存リスク高)/ H-08 / H-10 の
  緩和策は従来 UI の画面遷移境界を前提としており、一枚盤面で成立するかの

- **常設受付キューの氏名表示範囲**(2026-07-31 checker M-5 追加)— 投薬カウンター
  設置端末では待合の第三者から画面が視認されうる。常設キューの患者氏名を
  イニシャル・受付番号へ縮退する選択肢と設置環境前提【製品権限 + privacy】
- **UIX-001 禁止 #12(破壊的操作のワンクリック実行)/ #15(操作短縮を患者安全より
  優先しない)に対する本方向の明示評価**(2026-07-31 checker H-6 追加)— 本決定記録は
