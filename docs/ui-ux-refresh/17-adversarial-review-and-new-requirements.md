## 2. D-2 の設計骨格 — 「1操作・2段分離」

「確定」と「外部登録」を同一トランザクションにしない(敵対的所見 AF-1 の帰結):

```
薬剤師の1操作(最終確定)
 ├─ 段1: ローカル確定(同一トランザクション・不可逆)
 │   確定者・日時・対象版を記録 / DOM-004 遷移ガード+scope 検証(prescription/dispensing:confirm)
 │   / 版不一致は 412 で失敗(14号 §7.2-4)
 └─ 段2: 調剤結果登録ジョブを outbox へ積む(外部・再試行可能)
     PENDING_EXTERNAL_SYNC として常時可視(P-02)/ 登録完了まで「登録済み」と表示しない(H-03)
     / LOCAL_ONLY 中は自動でキュー蓄積 / 失敗・DLQ は同期状態(SCR-025)へ
```

- 段2の失敗は段1を巻き戻さない(確定は事実)。逆に段2だけの成功は存在しない(順序保証)。
- HPKI 電子署名の位置づけ(legal_compliance_matrix #7)は電子処方箋境界 SSOT の APPROVED 時に確定。
  **署名の実行時点・実行主体・段1/段2 のどちらに帰属するかは法務判断まで未決とする**
  (2026-07-31 checker H-5 訂正 — 当初記述「署名は段2のペイロード生成側」は法務未決事項の
  技術的先取りだった。署名が薬剤師の確認行為そのものに帰属すべきものなら、薬剤師が端末を
  離れた後に非同期 outbox ジョブが署名を実行する構成は署名者の意思・支配下の要件と衝突し、
  LOCAL_ONLY 中のキュー蓄積では署名時点で HPKI カードが不在でありうる。
  段1/段2 の**分離自体**は署名帰属の決定と独立に維持する)【法務 gate — legal_compliance_matrix #7】。
- UI は1ボタン(DestructiveActionDialog 系の二段階確認 — P-11)だが、完了表現は
  「確定済み ●」と「登録待ち ↻ / 登録済み ●」を**別 chip で並置**する(単一の緑チェックで束ねない)。
